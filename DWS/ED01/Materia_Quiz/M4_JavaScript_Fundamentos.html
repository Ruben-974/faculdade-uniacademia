1. Conceitos e Fundamentos Teóricos de JavaScript

JavaScript é uma das linguagens de programação mais populares e influentes do mundo. Compreender sua origem, seu papel no desenvolvimento web e suas características fundamentais é essencial para qualquer desenvolvedor que deseje construir aplicações web modernas e interativas.

1.1 História e Origem

A história do JavaScript começa em 1995, quando a Netscape Communications Corporation — criadora do navegador Netscape Navigator, líder de mercado na época — decidiu que precisava de uma linguagem de script simples para tornar as páginas web mais interativas. Naquele momento, a web era essencialmente estática: o HTML fornecia a estrutura, mas não havia como responder dinamicamente às ações do usuário.

Para resolver esse problema, a Netscape contratou Brendan Eich, um desenvolvedor que, em apenas 10 dias, criou a primeira versão da linguagem. A linguagem recebeu inicialmente o nome de Mocha, depois foi renomeada para LiveScript e, finalmente, para JavaScript.

A mudança para "JavaScript" foi uma decisão de marketing: a Netscape havia firmado uma parceria com a Sun Microsystems (criadora da linguagem Java), e o nome "JavaScript" foi escolhido para surfar na popularidade crescente do Java. É importante ressaltar que, apesar do nome similar, JavaScript e Java são linguagens completamente diferentes em termos de design, arquitetura e propósito.

Em 1996, a Microsoft criou uma linguagem compatível para o Internet Explorer, chamada JScript. Para evitar a fragmentação da linguagem, a Netscape submeteu o JavaScript à ECMA International (organização especializada em padrões), resultando na criação do padrão ECMAScript em 1997. Desde então, o JavaScript é oficialmente conhecido como ECMAScript, embora o nome "JavaScript" continue sendo o mais utilizado no dia a dia.

1.2 O Papel do JavaScript no Desenvolvimento Web

Para entender o papel do JavaScript, é útil pensar na web como uma "camada de tecnologias", cada uma com uma responsabilidade específica:

Tecnologia Responsabilidade Analogia
HTML Conteúdo e estrutura da página O esqueleto do corpo humano
CSS Layout e estilo visual A pele, o cabelo e as roupas
JavaScript Comportamento e interatividade Os músculos e o cérebro

Enquanto o HTML define o que está na página (parágrafos, títulos, imagens) e o CSS define como isso aparece (cores, fontes, posicionamento), o JavaScript define o que acontece quando o usuário interage com a página. É o JavaScript que permite:

  • Atualizações dinâmicas de conteúdo: Alterar textos, imagens e estilos em tempo real sem recarregar a página.
  • Respostas a eventos do usuário: Cliques, movimentos do mouse, digitação, rolagem, etc.
  • Validação de formulários: Verificar dados antes de enviá-los ao servidor.
  • Animações e efeitos visuais: Transições suaves, gráficos 2D/3D, vídeos interativos.
  • Comunicação assíncrona: Enviar e receber dados do servidor em segundo plano (AJAX/Fetch API).

O princípio da Separação de Interesses (Separation of Concerns) é fundamental: ao manter o conteúdo (HTML), a apresentação (CSS) e o comportamento (JavaScript) separados, os aplicativos web complexos tornam-se mais fáceis de manter, testar e escalar.

1.3 Características da Linguagem

1.3.1 Linguagem de Script (Interpretada)

JavaScript é uma linguagem de script, o que significa que não precisa ser compilada antes da execução. O código é interpretado diretamente pelo motor JavaScript do navegador no momento em que a página é carregada. Isso contrasta com linguagens como Java ou C++, que exigem uma etapa de compilação para gerar um arquivo executável.

Implicação prática: Essa característica torna o JavaScript extremamente ágil para desenvolvimento e prototipagem, pois não há um passo intermediário de compilação. Basta salvar o arquivo e recarregar a página para ver o resultado.

1.3.2 Client-Side (Executada no Cliente)

Originalmente, o JavaScript foi projetado para ser executado no lado do cliente (client-side), ou seja, no navegador do usuário. O servidor envia a página HTML — incluindo o código JavaScript — para o navegador, que então interpreta e executa esse código.

Vantagens do client-side:

  • Redução da carga do servidor: O processamento é feito no dispositivo do usuário, liberando recursos do servidor.
  • Respostas imediatas: O usuário recebe feedback instantâneo sem precisar aguardar uma ida ao servidor.
  • Experiência mais fluida: Interações como validação de formulário e animações ocorrem localmente.

Limitações do client-side:

  • Segurança: O código é visível e pode ser inspecionado ou modificado pelo usuário. Portanto, validações críticas devem ser sempre reforçadas no servidor.
  • Dependência do navegador: Diferentes navegadores podem ter implementações ligeiramente diferentes do motor JavaScript.
📌 Nota importante: Com o surgimento do Node.js em 2009, o JavaScript também passou a ser executado no lado do servidor (server-side), permitindo a criação de aplicações full-stack utilizando uma única linguagem. No entanto, o foco do material didático é o JavaScript client-side, executado no navegador.

1.3.3 Dinamicamente Tipada (Latent Typing)

JavaScript é uma linguagem dinamicamente tipada (também chamada de latently typed). Isso significa que não é necessário declarar o tipo de uma variável ao criá-la. O tipo é inferido automaticamente pelo motor JavaScript em tempo de execução, e uma mesma variável pode armazenar valores de tipos diferentes ao longo da execução do programa.

let valor = 3;        // valor é um Number
valor = "texto";      // agora valor é uma String
valor = null;         // agora valor é null

Essa flexibilidade é poderosa, mas exige disciplina do programador para evitar erros de tipo inesperados.

1.3.4 Baseada em Protótipos (Prototype-Based)

Diferente de linguagens orientadas a objetos clássicas como Java, que utilizam classes e herança de classe, o JavaScript utiliza um sistema de objetos baseado em protótipos. Nesse modelo, objetos podem ter protótipos (outros objetos) dos quais herdam comportamentos e propriedades, sem a necessidade de uma classe formal.

Implicação: O JavaScript é uma linguagem extremamente flexível e dinâmica, permitindo que objetos sejam modificados em tempo de execução — algo que é impossível em linguagens com tipagem estática e classes rígidas.

1.3.5 Case Sensitive

JavaScript é case-sensitive, ou seja, diferencia letras maiúsculas de minúsculas. Isso se aplica a palavras-chave, nomes de variáveis, nomes de funções e operadores.

let nome = "João";   // variável 'nome'
let Nome = "Maria";  // variável 'Nome' (diferente de 'nome')
let NOME = "José";   // variável 'NOME' (diferente de 'nome' e 'Nome')

Essas três variáveis são completamente distintas para o JavaScript.

1.4 Sintaxe Básica

1.4.1 Inserção no HTML

O código JavaScript pode ser inserido no HTML de três formas principais:

1. Diretamente no HTML (inline): Usando a tag <script> dentro do <body> ou <head>.

<script type="text/javascript">
  document.write("Aqui é JavaScript!");
</script>

2. Atributos de eventos em elementos HTML:

<button onclick="alert('Olá!')">Clique aqui</button>

3. Arquivo externo (recomendado):

<script src="script.js"></script>

Boas práticas: A terceira abordagem é a mais recomendada, pois mantém o código JavaScript separado do HTML, facilitando a manutenção e o reaproveitamento.

1.4.2 Comentários

JavaScript suporta dois tipos de comentários, com a mesma sintaxe do C++:

  • Comentário de uma linha: // Este é um comentário
  • Comentário de múltiplas linhas: /* Este é um comentário mais longo */

Importante: Comentários não podem ser aninhados. /* ... /* ... */ ... */ causará um erro de sintaxe.

1.4.3 Ponto e Vírgula

As instruções em JavaScript são separadas por ponto e vírgula (;). Embora o JavaScript possua um mecanismo de Inserção Automática de Ponto e Vírgula (ASI), que permite omitir o ; quando cada instrução está em sua própria linha, é considerado boa prática sempre escrever o ponto e vírgula, pois isso reduz a probabilidade de erros sutis no código.

// Boa prática
let x = 5;
let y = 10;
let soma = x + y;

// Funciona, mas não é recomendado
let x = 5
let y = 10
let soma = x + y

1.4.4 Estrutura de Blocos

Blocos de código são delimitados por chaves { }, assim como em Java e C++.

if (condicao) {
  // bloco de código
  console.log("Verdadeiro");
} else {
  console.log("Falso");
}

1.5 Variáveis e Tipos de Dados

1.5.1 Declaração de Variáveis

JavaScript possui três formas de declarar variáveis:

Palavra-chave Escopo Mutável Quando usar
var Função ou global Sim Evitar em código moderno (escopo confuso)
let Bloco Sim Padrão atual para variáveis mutáveis
const Bloco Não (reassignação) Padrão para constantes 
var nome = "João";        // Escopo de função
let idade = 25;           // Escopo de bloco
const PI = 3.14159;       // Escopo de bloco, não pode ser reatribuído

Observação: Embora const impeça a reatribuição, se o valor for um objeto ou array, seu conteúdo interno ainda pode ser modificado.

1.5.2 Tipos de Dados

JavaScript possui tipos primitivos e tipos de objeto:

Tipos Primitivos:

  • String: Sequência de caracteres (ex: "texto", 'texto')
  • Number: Números inteiros e decimais (ex: 42, 3.14)
  • Boolean: true ou false
  • null: Ausência intencional de valor
  • undefined: Valor não atribuído
  • Symbol: Identificador único (ES6)
  • BigInt: Números inteiros de precisão arbitrária (ES2020)

Tipos de Objeto:

  • Object: Coleção de pares chave-valor
  • Array: Lista ordenada de valores
  • Function: Bloco de código executável
  • Date, RegExp, etc.: Objetos especializados
let nome = "Maria";           // String
let idade = 30;               // Number
let ativo = true;             // Boolean
let endereco = null;          // null
let telefone;                 // undefined
let hobbies = ["ler", "correr"]; // Array
let pessoa = { nome: "Ana", idade: 28 }; // Object

Curiosidade: Em JavaScript, null e undefined são valores distintos. null é um valor atribuído explicitamente, enquanto undefined indica que uma variável foi declarada mas ainda não recebeu valor.

1.6 Escopo de Variáveis

O escopo define onde uma variável pode ser acessada no código. JavaScript possui três tipos principais de escopo:

  • Escopo Global: Variáveis declaradas fora de qualquer função são acessíveis em todo o código.
  • Escopo de Função: Variáveis declaradas com var dentro de uma função são acessíveis apenas dentro dessa função.
  • Escopo de Bloco: Variáveis declaradas com let ou const dentro de um bloco { } são acessíveis apenas dentro desse bloco.
var global = "Acessível em todo lugar";

function exemplo() {
  var funcao = "Acessível apenas dentro da função";
  
  if (true) {
    let bloco = "Acessível apenas dentro deste bloco";
    const TAMBEM_BLOCO = "Também apenas neste bloco";
  }
  
  // console.log(bloco); // ERRO: bloco não está definido aqui
}

1.8 Considerações Finais sobre os Fundamentos

O JavaScript é uma linguagem versátil, dinâmica e onipresente na web moderna. Seus fundamentos — a história, o papel como terceira camada da web, as características de linguagem interpretada e client-side, a sintaxe inspirada em C/Java, e o sistema de variáveis e escopos — formam a base sobre a qual todo o desenvolvimento front-end é construído.

Dominar esses conceitos é o primeiro passo para avançar em tópicos mais complexos como manipulação do DOM, eventos, funções assíncronas, Fetch API, frameworks modernos (React, Vue, Angular) e Node.js.

2. Recursos da Linguagem: Sintaxe e Estruturas

O JavaScript oferece um conjunto rico de recursos sintáticos e estruturas de dados que permitem construir desde pequenos scripts de validação até aplicações complexas. Este tópico explora as variáveis, os tipos de dados, os operadores, as estruturas de controle, as funções, os arrays e objetos, além dos métodos nativos mais utilizados no material didático.

2.1 Variáveis e Constantes

2.1.1 var (Escopo de Função ou Global)

A palavra-chave var foi a única forma de declarar variáveis até o ECMAScript 2015 (ES6). Variáveis declaradas com var têm escopo de função (ou global, se declaradas fora de qualquer função). Isso significa que elas são acessíveis em toda a função onde foram declaradas, independentemente de estarem dentro de um bloco if, for ou while.

Além disso, var sofre hoisting: a declaração da variável é "elevada" ao topo do seu escopo, mas a atribuição de valor permanece na linha original.

console.log(nome); // undefined (não gera erro)
var nome = "João";

Problema do var: Por ter escopo de função, uma variável declarada dentro de um bloco for vaza para fora do bloco:

for (var i = 0; i < 3; i++) {
  // ...
}
console.log(i); // 3 (i ainda está acessível!)

2.1.2 let (Escopo de Bloco)

Introduzido no ES6, let resolve o problema do vazamento de escopo. Variáveis declaradas com let têm escopo de bloco: são acessíveis apenas dentro do bloco { } onde foram declaradas.

if (true) {
  let mensagem = "Olá";
  console.log(mensagem); // "Olá"
}
// console.log(mensagem); // ERRO: mensagem não está definida

Hoisting com let: let também sofre hoisting, mas a variável não é inicializada até a linha da declaração. Isso cria a TDZ (Temporal Dead Zone):

// console.log(x); // ReferenceError: Cannot access 'x' before initialization
let x = 10;

2.1.3 const (Constante com Escopo de Bloco)

const também foi introduzido no ES6 e tem escopo de bloco. A diferença fundamental é que uma variável const não pode ser reatribuída após sua declaração.

const PI = 3.14159;
// PI = 3.14; // ERRO: Assignment to constant variable.

Importante: const impede a reatribuição, mas se o valor for um objeto ou array, seu conteúdo interno ainda pode ser modificado:

const usuario = { nome: "Ana" };
usuario.nome = "Maria"; // Permitido (modifica a propriedade)
// usuario = {}; // ERRO (reatribuição)

2.1.4 Comparação entre var, let e const

Característica var let const
EscopoFunção ou globalBlocoBloco
ReatribuiçãoSimSimNão
HoistingSim (inicializado como undefined)Sim (TDZ)Sim (TDZ)
Uso recomendadoEvitar em código novoVariáveis mutáveisConstantes
✅ Boa prática: Utilize const por padrão e let apenas quando a variável precisar ser reatribuída. Evite var em código novo.

2.2 Tipos de Dados

O JavaScript possui oito tipos de dados: sete primitivos e um tipo de objeto (Object).

2.2.1 Tipos Primitivos

  1. String: Sequência de caracteres. Ex: "Olá", 'JavaScript'.
  2. Number: Números inteiros e de ponto flutuante. Ex: 42, 3.14. O JavaScript não diferencia inteiros de floats — 3 e 3.0 são o mesmo valor.
  3. Boolean: true ou false.
  4. Undefined: Uma variável declarada mas não inicializada tem o valor undefined.
  5. Null: Representa a ausência intencional de valor.
  6. Symbol: Introduzido no ES6, é um valor único e imutável, frequentemente usado como chave de propriedades de objetos.
  7. BigInt: Introduzido no ES2020, permite representar números inteiros com precisão arbitrária.
let nome = "Maria";           // String
let idade = 30;               // Number
let ativo = true;             // Boolean
let endereco = null;          // Null
let telefone;                 // Undefined
let id = Symbol("id");        // Symbol
let numeroGrande = 9007199254740991n; // BigInt

2.2.2 Tipo Object

O tipo Object é a base para estruturas mais complexas, como arrays, funções, datas e objetos literais.

let pessoa = { nome: "Ana", idade: 28 }; // Objeto literal
let hobbies = ["ler", "correr"];          // Array (também é um objeto)

2.2.3 Verificação de Tipo com typeof

O operador typeof retorna uma string indicando o tipo do operando:

typeof "texto"     // "string"
typeof 42          // "number"
typeof true        // "boolean"
typeof undefined   // "undefined"
typeof null        // "object" (particularidade histórica)
typeof Symbol()    // "symbol"
typeof 123n        // "bigint"
typeof {}          // "object"
typeof []          // "object"
typeof function(){} // "function"

Observação: typeof null retorna "object" por uma decisão histórica da linguagem, o que é amplamente considerado um bug, mas permanece por compatibilidade.

2.4 Estruturas de Controle

2.4.1 Condicional if...else

if (idade >= 18) {
  console.log("Maior de idade");
} else {
  console.log("Menor de idade");
}

Encadeamento else if:

if (nota >= 7) {
  console.log("Aprovado");
} else if (nota >= 5) {
  console.log("Recuperação");
} else {
  console.log("Reprovado");
}

Operador Ternário: Uma forma concisa de if/else em uma única expressão:

const mensagem = idade >= 18 ? "Maior" : "Menor";

2.4.2 Condicional switch

switch (diaSemana) {
  case 1:
    console.log("Segunda-feira");
    break;
  case 2:
    console.log("Terça-feira");
    break;
  case 3:
    console.log("Quarta-feira");
    break;
  default:
    console.log("Outro dia");
}

Importante: O break é essencial para evitar que a execução "caia" para os casos seguintes (fall-through).

2.4.3 Laço for

for (let i = 0; i < 5; i++) {
  console.log(`Iteração ${i}`);
}

Variações: for...of (para iterar sobre arrays) e for...in (para iterar sobre propriedades de objetos).

2.4.4 Laço while

let contador = 0;
while (contador < 5) {
  console.log(contador);
  contador++;
}

2.4.5 Laço do...while

let numero;
do {
  numero = prompt("Digite um número maior que 10:");
} while (numero <= 10);

2.5 Funções

2.5.1 Declaração de Função (Function Declaration)

function somar(a, b) {
  return a + b;
}

console.log(somar(2, 3)); // 5

2.5.2 Expressão de Função (Function Expression)

const somar = function(a, b) {
  return a + b;
};

console.log(somar(2, 3)); // 5

2.5.3 Arrow Functions (Funções Seta)

const somar = (a, b) => a + b;

Características:

  • Se houver apenas um parâmetro, os parênteses podem ser omitidos: const dobro = x => x * 2;
  • Se o corpo for uma única expressão, as chaves e o return podem ser omitidos.
  • Arrow functions não possuem seu próprio this — elas herdam o this do contexto onde foram definidas.
nome.addEventListener("input", () => marcarCampo(nome, validarNome(nome.value)));

2.5.4 Parâmetros e Retorno

function validarNome(valor) {
  return valor.trim().length > 2;
}

2.5.5 Callbacks

form.addEventListener("submit", function(event) {
  event.preventDefault();
  // ...
});

3. Manipulação de DOM e Eventos

A manipulação do DOM (Document Object Model) e o tratamento de eventos são o coração da interatividade em JavaScript. É através desses recursos que o código JavaScript consegue "conversar" com a página HTML, lendo dados inseridos pelo usuário, alterando conteúdos dinamicamente e respondendo a ações como cliques, digitação e envio de formulários.

3.1 O que é o DOM (Document Object Model)

O DOM é uma interface de programação que representa a estrutura de um documento HTML (ou XML) como uma árvore de objetos. Quando o navegador carrega uma página HTML, ele cria uma representação interna dessa página na memória, onde cada elemento HTML se torna um nó (node) dessa árvore.

<!DOCTYPE html>
<html>
<head>
  <title>Minha Página</title>
</head>
<body>
  <h1>Cadastro de Usuário</h1>
  <form id="formCadastro">
    <input type="text" id="nome" placeholder="Digite seu nome">
    <button type="submit">Cadastrar</button>
  </form>
  <div id="resultado"></div>
</body>
</html>

Representação em árvore DOM:

document
└── html
    ├── head
    │   └── title
    │       └── "Minha Página"
    └── body
        ├── h1
        │   └── "Cadastro de Usuário"
        ├── form#formCadastro
        │   ├── input#nome
        │   └── button
        └── div#resultado

O objeto document é a raiz dessa árvore e representa todo o documento HTML.

3.6 Fluxo de Eventos: Borbulhamento e Captura

Quando um evento ocorre, ele se propaga pela árvore DOM em três fases:

  1. Fase de Captura (Capture Phase): O evento desce da raiz até o elemento alvo.
  2. Fase de Alvo (Target Phase): O evento atinge o elemento alvo.
  3. Fase de Borbulhamento (Bubbling Phase): O evento sobe do elemento alvo de volta até a raiz.

3.9 Exemplo Completo: Ciclo de um Cadastro com DOM e Eventos

// 1. Seleção de elementos
const form = document.getElementById("formCadastro");
const nome = document.getElementById("nome");
const email = document.getElementById("email");
const idade = document.getElementById("idade");
const resultado = document.getElementById("resultado");

// 2. Validação em tempo real
nome.addEventListener("input", () => marcarCampo(nome, validarNome(nome.value)));
email.addEventListener("input", () => marcarCampo(email, validarEmail(email.value)));
idade.addEventListener("input", () => marcarCampo(idade, validarIdade(Number(idade.value))));

// 3. Interceptação do submit
form.addEventListener("submit", function(event) {
  event.preventDefault();
  
  const nomeValido = validarNome(nome.value);
  const emailValido = validarEmail(email.value);
  const idadeValida = validarIdade(Number(idade.value));

  marcarCampo(nome, nomeValido);
  marcarCampo(email, emailValido);
  marcarCampo(idade, idadeValida);

  if (nomeValido && emailValido && idadeValida) {
    adicionarUsuario(nome.value, email.value, Number(idade.value));
    mostrarResultado("Cadastro realizado com sucesso!<hr>" + listarUsuarios(), "success");
    form.reset();
    [nome, email, idade].forEach(i => i.classList.remove("is-valid", "is-invalid"));
  } else {
    mostrarResultado("Há erros no formulário. Verifique os campos.", "danger");
  }
});

5.1 Validação em Tempo Real

5.1.1 Conceito: O Evento input

O evento input é disparado sempre que o valor de um elemento é alterado pelo usuário. Isso inclui digitação, colagem, recorte, arrastar e soltar, e autocompletar.

💡 Diferença crucial: O evento change só dispara quando o elemento perde o foco após ter sido alterado. Já o input dispara imediatamente a cada alteração.

5.1.2 Estrutura da Validação em Tempo Real

5.2 Interceptação do Envio do Formulário

form.addEventListener("submit", function(event) {
  event.preventDefault(); // evita o reload padrão
  resultado.innerHTML = '<div class="alert alert-info">Formulário recebido (JS interceptou o submit)</div>';
});

Sem o preventDefault(): O navegador tentaria enviar o formulário, causando um reload que apagaria todos os dados.

Com o preventDefault(): O JavaScript assume o controle total e pode processar os dados como quiser.

5.7 Fluxo Completo de Uso: Do Preenchimento ao Cadastro

  1. Acesso à página: O usuário abre o index.html. O HTML é carregado, o Bootstrap 5 é baixado via CDN e o script.js é executado.
  2. Digitação no campo "Nome": A cada tecla, o evento input dispara. Se o comprimento for menor que 3, a borda fica vermelha; ao atingir 3 ou mais, fica verde.
  3. Digitação no campo "Email": Ao incluir "@" e ".", a borda fica verde.
  4. Digitação no campo "Idade": Ao digitar um número entre 18 e 120, a borda fica verde.
  5. Clique em "Cadastrar": O evento submit é disparado. event.preventDefault() cancela o reload.
  6. Processamento e Feedback: O usuário é adicionado ao array e um alerta verde com a lista é exibido.
  7. Limpeza: O formulário é resetado e as classes visuais são removidas.

5.8 Desafios e Extensões do Projeto

  1. Persistência com localStorage: Salvar o array usuarios no localStorage. 
    localStorage.setItem("usuarios", JSON.stringify(usuarios));
// Recuperar: JSON.parse(localStorage.getItem("usuarios")) || []
  2. Remoção de usuários: Adicionar um botão "Excluir" ao lado de cada usuário na lista.
  3. Edição de usuários: Permitir editar um cadastro existente.
  4. Validação de CPF: Adicionar um campo de CPF com validação de dígitos verificadores.
  5. Máscaras de input: Usar bibliotecas como IMask.js para formatar CPF, telefone e data.
  6. Envio para o servidor: Substituir o armazenamento em memória por uma chamada fetch() para uma API.
  7. Feedback com aria-live: Adicionar o atributo aria-live="polite" na <div id="resultado">.
  8. Validação com RegExp: Substituir a validação simplificada de email por uma expressão regular robusta.
